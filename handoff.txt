Current storage situation
--------------------------

DIHI runs in Docker under WSL2 on Windows. The repository currently stores
runtime data under ./data. Current data size is approximately 16 GB:

- data/media-strict: about 14 GB
- data/media-fallback: about 849 MB
- data/bestfallback: about 536 MB
- data/media-catalog.db: about 222 MB

The Makefile now provides:

- make data-size
- make data-migrate DEST_DATA_DIR=/mnt/e/dihi-data

data-migrate copies the current data tree without deleting the source. Stop
Docker before migrating:

    docker compose down
    make data-migrate DEST_DATA_DIR=/mnt/e/dihi-data

Then configure the destination:

    cp .env.example .env
    sed -i 's#DIHI_DATA_DIR=./data#DIHI_DATA_DIR=/mnt/e/dihi-data#' .env
    make data
    make data-size
    docker compose up -d --build

docker-compose.yaml uses ${DIHI_DATA_DIR:-./data} for all persistent mounts.
Make also loads .env so make data initializes the configured destination.
.env.example is tracked; the real .env is ignored.

WSL USB diagnosis
-----------------

The current WSL environment has /mnt/c mounted to the Windows C: drive, but
/mnt/e is only an empty directory and is not the USB drive. `df -h /mnt/e`
currently reports the WSL root filesystem, which proves the USB is not mounted
there.

In Windows PowerShell, identify the USB:

    Get-Volume | Format-Table DriveLetter, FileSystem, SizeRemaining, Size

If it has no drive letter, assign one through Disk Management. Then restart
WSL from PowerShell:

    wsl --shutdown

Reopen WSL and verify:

    df -h /mnt/e
    ls -la /mnt/e

The USB should use NTFS if possible. FAT32 has a 4 GB per-file limit and is
not suitable for potentially large video files. Keep the USB connected while
Docker is running.

Important storage caveat
------------------------

Moving DIHI's bind-mounted data does not move Docker Desktop's own image/build
cache. Moving the Docker disk image is a separate Docker Desktop operation.
USB/DrvFs performance and whether the SQLite catalog/archive should remain on
native WSL storage are still roadmap items.
